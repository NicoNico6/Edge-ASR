# 证明它能用

直接检查真实产物：在目标上运行、读实际的值、看 diff、听或看输出。不从代理、自述、「编译通过」推断。

**为什么：** 未验证的工作正确性未知。间接验证（文件时间、子 agent 的报告、模拟器结果）看起来便宜，按错误推断行动的代价高得多。

**做法：**
- 检查真实的东西：在板上跑交付的二进制，读实际的输出张量，播放实际生成的音频。
- 验证失败时，先怀疑观测方法，再怀疑系统。
- 最强的证明是一个能重跑同一比较的确定性脚本，把它和输出一起留给审阅者。
- 子 agent 说「完成」不等于完成，复核它的产物。
