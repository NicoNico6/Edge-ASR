# 在真实负载上验证

候选必须在真实负载上通过验证：来自产品或客户的真实输入、代表性的形状分布、agent 迭代时没见过的留出集。只在合成输入或固定测试输入上通过的候选不晋升。

**为什么：** 优化循环会钻测试的空子。Kernel Design Agents 的公开报告里，有两个早期候选靠硬编码测试输入的统计规律拿到 3.74 倍和 5.16 倍，在真实 Kimi 数据上都失败了，最终有效结果是 2.96 倍（转述，来自对 NVlabs/kda 的报道）。合成数据恰好落在容差内而一直通过，是端侧移植里同样常见的失败。

**做法：**
- 契约里写明真实负载的来源和留出集位置（**task-contract** skill）。留出集不给迭代中的 agent 看，只在晋升时跑。
- 按真实负载的形状分布选测试形状，包括最大、最小、非对齐、变长。不随手造输入。
- 剖析和基准用真实张量（从真实样本 dump 出的权重与激活），不用随机数。
- 加反钻空子的检查：随机化输入顺序和数值、换一批未见样本、检查输出是否依赖输入、检查代码里是否有针对测试形状或数值的特判。
- 结果好得超出物理上限估算或超出预期很多时，先当成测试被钻了空子处理（**principle-explain-the-number**）。

**边界：** 区别于 **principle-board-is-truth**（在哪里测）和 **principle-worst-case-first**（测哪些边缘）。这条管测试本身能不能被候选利用。
