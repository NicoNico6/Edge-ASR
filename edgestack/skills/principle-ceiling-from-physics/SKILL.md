# 从物理算上限

先用物理算出天花板：roofline（字节除以带宽，操作数除以峰值）、Amdahl（被优化部分占比决定最大收益）、每步搬运字节乘以步频对比可用带宽。实测离天花板多远，决定下一步做什么。

**为什么：** 不知道上限时，无法判断一个优化是快接近极限还是还差很远，也无法发现一个「好得不可能」的数字其实测错了。

**做法：**
- 用 **roofline** skill 或 `scripts/roofline.py`，输入设备带宽、算力、可用内存、各组件参数量与位宽、所需步频。
- 实测比估算慢 1.5 倍以上：瓶颈不在权重搬运，先做逐阶段剖析（**profile** skill），不要继续压模型。
- 实测比上限还快：先怀疑测量（缓存命中、没做完的工作、错误的计时区间）。
- 估算和实测并排写进总账，估算标「推断」，实测标「实测」。

**边界：** 区别于 **principle-explain-the-number**，那条在测完之后找限制因素；这条在动手之前算边界。
