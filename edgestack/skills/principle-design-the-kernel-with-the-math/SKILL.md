# 结构和它的执行形式一起设计

改一个结构时，同时决定它在目标硬件上怎么算：用什么分块或扫描形式、每步读多少字节、状态多大、需要哪些算子。数学上等价或更强的结构，如果没有高效的执行形式，在端侧就不是更好的结构。

**为什么：** 好的高效结构往往是为了能高效执行而主动收窄的。例如 KDA 把一般的 DPLR 转移矩阵约束成两个低秩向量都绑定到 key 上，换来更少的矩阵乘和更简单的分块算法（原文：arXiv 2510.26692 摘要称这一特化相比一般 DPLR 显著减少计算）。反过来，表达力更强但只能逐 token 串行算、或依赖目标 NPU 不支持的扫描算子的结构，上板后会比朴素结构更慢。

**做法：**
- 每个候选结构写出：每步（或每块）读多少字节、计算量、状态或缓存大小随序列长度怎么增长、所需算子、分块大小等固定形状。
- 先对候选做包络普查和物理上限估算（**opcensus**、**roofline**），再训练。
- 有参数化上的选择时，优先选和高效 kernel 对得上的那个（矩阵乘为主、固定块大小、少的非矩阵乘操作），并验证表达力损失在噪声内。
- 结构、kernel、推理实现一起交付，参考实现用来对拍。
- 记录数值非确定性来源（分块大小、batch 组成会不会改变结果），给确定性开关。

**边界：** 区别于 **principle-envelope-before-port**（已有结构能不能跑）和 **principle-cost-function-is-the-constraint**（搜索优化什么）。参考 `../edge-mode/references/architecture-patterns.md`。
