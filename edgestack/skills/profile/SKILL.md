# Profile

## 原则

剖析的是交付的那条流水线，不是单独的模型前向。剖析开销会拖慢运行，所以剖析运行的数字不用于汇报，汇报用不开剖析的运行。

## 步骤

1. 定每步预算：实时类任务按帧或块的时长（例如每 80 ms 一步），吞吐类按目标每秒步数。
2. 打点或用平台工具（Nsight、perf、py-spy、厂商 profiler、cycle 计数器）记录每个阶段：预处理、每个模型组件、后处理、解码与采样、主机侧下发、拷贝、同步、精度转换。
3. 做阶段表：阶段、时间（中位与 p99）、占比、单元、是否在关键路径上。加一行「未归类」，超过 10% 先补打点。
4. 跨界开销单独成行（**principle-price-every-crossing**）。kernel 很多而单个很短时，看主机侧下发时间是否超过执行时间。
5. 多单元时画时间线，找空泡和本该并行却串行的阶段。
6. 每个阶段对照上限估算（**roofline** skill），标出离上限最远的阶段，那里是下一个杠杆。

## 输出

阶段表、时间线截图或文本、离上限最远的三个阶段、未归类比例、剖析运行的口径。
