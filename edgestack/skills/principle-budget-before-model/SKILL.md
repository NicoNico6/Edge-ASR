# 预算先于模型

先写预算卡，再碰模型。预算卡列出质量底线、时间（时延、实时率、吞吐）、空间（每级存储的容量与每步搬运字节）、能量与热、稳定性规格，并标出哪一条是硬墙。

**为什么：** 没有预算时，优化会追最容易动的那个数字。硬约束不满足的方案再好也不能发货，所以硬约束是准入条件，不是优化目标。压缩、移植、调度的每个选择都要能回指到预算卡上的某一行。

**做法：**
- 用 **budget** skill 和 `templates/budget-card.md`。每一行写数值、单位、口径和来源（客户合同、硬件手册、实测）。
- 区分硬墙（过不去就不能发货）和软目标（越好越好）。硬墙先过，软目标再比。
- 预算会随实测更新。手册值被实测推翻时，改卡并在总账记一行。

**边界：** 区别于 **principle-cost-function-is-the-constraint**，那条管搜索优化什么；这条管工作开始前约束写没写下来。
