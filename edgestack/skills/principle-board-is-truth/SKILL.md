# 板上为真

估算、模拟器排名、x86 仿真、别人的报告都是假设，板上实测才是结论。测量对象是将要交付的产物，走交付的同一条路径：同一份预处理、守卫、解码配置、二进制。不为测量另写一套实现。

**为什么：** 估算常被推翻：融合省下的时间、量化模拟的损伤、模拟器的正确性都可能和硬件不符。另写一套评测代码会和产品路径慢慢分叉，最后测的不是要发货的东西。

**做法：**
- 每个估算旁边写「推断」，等实测后补上「实测」数字。
- 模拟到板上的对齐是一道门：两边差异在约定阈值内，才信模拟器的排名。
- 评测脚本调用产品代码路径，不复制粘贴一份。离线评测和设备运行共享同一份配置文件。
- 产品里有的守卫（循环检测、长度上限、回退）在评测里也要开着，守卫之后的指标才是部署口径。

**边界：** 区别于 **principle-prove-it-works**（验证产出是真的）和 **principle-parity-ladder**（怎么逐级对齐）。
