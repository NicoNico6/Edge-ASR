# 证伪也是资产

失败的路径和成功的一样入账：预期是什么、实测是什么、为什么不同。被证伪的估算是对你的硬件模型或模型理解的一次校准。

**为什么：** 不记录的失败会被别人（或几周后的自己）重新尝试。估算和实测的差距本身是信息：它告诉你哪部分认识是错的。

**做法：**
- 总账里设「已证伪」一栏：路径、预期、实测、原因、发现日期。
- 估算错了要写清楚错在哪个假设上，并更新预算卡或硬件画像。
- 实验配方的错误（例如 v1 的做法错误、v3 修正）记在配方修正表里，写清后果。

**边界：** 区别于 **principle-scope-every-conclusion**（结论的适用范围）。
