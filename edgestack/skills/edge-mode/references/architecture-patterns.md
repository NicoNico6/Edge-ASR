# 硬件相关的结构模式

这份表按「省了什么字节或计算、付出什么、在端侧要注意什么」整理常见结构。用于 **Architecture design** 和 **Custom model** playbook。表里的事实标「原文」（读过论文摘要或正文）或「转述」（二手），用之前读原文和源码（**principle-cite-precedent**）。

## 序列混合（注意力及其替代）

| 模式 | 省了什么 | 付出什么 | 端侧要注意 |
|---|---|---|---|
| GQA / MQA | KV cache 按头数比例缩小 | 少量质量 | 几乎所有运行时支持，首选 |
| MLA（潜在 KV 压缩） | KV cache 存低秩潜变量 | 解码时的上投影计算，实现复杂 | 吸收矩阵的推理形式要运行时支持 |
| 滑动窗口 / 局部注意力 | 缓存上限固定为窗口 | 远距离依赖 | 固定形状，适合 NPU；流式 ASR 常用 |
| 稀疏注意力（按块选择） | 长序列的读取量 | 选择逻辑、不规则访存 | 不规则 gather 在 NPU 上常常慢 |
| 线性注意力 / delta rule（Gated DeltaNet、KDA） | 缓存变成固定大小的状态，解码每 token 成本不随长度增长 | 精确检索与复制能力弱于全注意力；需要分块扫描 kernel | 分块算法（块内并行、块间递归）要有对应 kernel；状态读写是每步的字节 |
| SSM（Mamba2 等） | 同上，固定状态 | selective scan 算子 | 扫描算子在多数 NPU 上不支持或很慢，通常只能跑在 GPU/CPU |
| 混合（线性层与全注意力层按比例交错） | 大部分层用固定状态，少数层保留检索能力 | 比例要实测选 | KDA 与 MLA 按 3:1 交错，摘要称相比全 MLA 在相同训练配方下更好，KV cache 最多减少 75%，1M 上下文解码吞吐最多 6 倍（原文，「最多」值）；全注意力层用 NoPE，位置信息交给线性层（转述）。Qwen 系的 Gated DeltaNet 混合、Nemotron-H 的 Mamba2 混合是同类思路（转述） |

KDA 的设计值得当作样本看（原文与转述混合，以论文为准）：在 Gated DeltaNet 上把门控做细到通道级，让有限状态用得更好；把 DPLR 转移约束成绑定到 key 的形式以减少计算；分块（转述为每块 64）做块内并行、块间递归；kernel、vLLM 实现和权重一起开源；有第三方文档提到这类线性注意力后端不支持 batch 不变模式，结果会随 batch 组成变化（转述）。可迁移的是结构：受约束的参数化换高效 kernel、比例实测选、结构与 kernel 一起交付、写明非确定性。常数（比例、块大小、门控粒度）要按自己的规模和硬件重调。

## 参数与计算

| 模式 | 省了什么 | 付出什么 | 端侧要注意 |
|---|---|---|---|
| MoE | 每 token 只算激活的专家 | 总参数大，内存或存储压力 | 总参数决定存放，激活参数决定每步字节；配合分层存放和专家缓存（**Memory hierarchy**） |
| 共享专家 / 专家裁剪 | 常用能力常驻 | 裁剪后能力下降 | 按路由统计裁剪，再修复 |
| 权重共享 / 层复用 | 体积 | 表达力 | 体积是硬墙时有用，每步字节不变 |
| 低秩分解 | 参数与计算 | 精度 | 小矩阵乘在 NPU 上效率低，先测 |

## 解码与生成

| 模式 | 省了什么 | 付出什么 | 端侧要注意 |
|---|---|---|---|
| MTP / 草稿头 + 推测解码 | 每次前向产出多个 token | 验证开销、接受率依赖内容 | 只在实测接受率与开销划算的条件下开（**Engine feature**） |
| 少步生成（DMD 等分布匹配蒸馏） | 扩散或流模型的采样步数 | 多样性、训练复杂度 | 用感知评测验收 |
| 非自回归 / CTC / RNN-T | 解码串行性 | 语言建模能力 | 流式识别常用；配缓存感知的编码器 |
| 缓存感知的流式编码器 | 重复计算 | 前瞻受限 | 块大小与前瞻决定时延与精度 |

## 从已有模型转换

把预训练的全注意力模型改成高效结构，常见做法是替换部分层（例如换成线性注意力或局部注意力）后蒸馏修复，比从头训练便宜。先在小规模上验证替换比例和修复配方，再放大；用检索、复制、长上下文类评测守门，这些能力最容易丢。

## 选结构时写下

每步字节、计算量、状态或缓存随长度的增长、所需算子与支持情况、固定形状、预计质量风险、先例与源码。这些写进 **Architecture design** playbook 的候选表。
