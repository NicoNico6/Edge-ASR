### Engine feature（引擎能力）

**你拥有新能力的正确性、实测收益和它在哪些条件下才值得开启。**

1. 先写任务契约（**task-contract** skill）。写清能力和预期：推测解码、缓存层、批处理、新后端、新量化格式。预期收益来自哪个机制，依赖什么条件。
2. 先确认输出等价性的定义：逐 token 一致、分布一致、还是允许的误差范围。推测类能力要验证接受率和输出一致。
3. 加开关，默认关闭。新代码路径和旧路径能在同一二进制里切换，方便对比和回退。
4. 在尺子上测：吞吐、时延、内存、质量，不同输入类型分开报（例如代码编辑和普通文本）。
5. 只在实测收益超过开销的条件下默认开启，其他条件保持关闭，在文档里写明。
6. 数值依赖调度或缓存状态时，提供确定性开关。
7. 未测的配置、结果混杂或有噪声的配置，在文档里如实列出。

**回复：** 能力、等价性验证、分条件的实测收益、默认开启的条件、未测或结果混杂的配置。
