# 解释这个数字

一个实测数字是关于系统的主张。相信它之前，说出限制它的资源，并排除它测的其实是别的东西。

**为什么：** 出了错的运行也会打印出看起来合理的数字。失败的请求、命中缓存跳过的工作、没执行的代码、一边用了默认设置、运行间噪声，都会产生「看起来不错」的结果。说不出它为什么没有再快一倍，就不知道自己测了什么。

**做法：**
- 问「为什么不是两倍？」从剖析或硬件计数器里找到限制因素（带宽、某个计算单元、锁、下发、热），再映射回代码。读代码猜出来的不算。
- 列出这个数字还可能在测什么（错误、跳过的工作、未调优的一边、噪声、占比太小的部分），逐条用证据排除。
- 证据和数字放在一起：运行次数、范围、限制因素、物理上限估算。

性能数字走完整的 **benchmark-checklist** skill。评测数字问同样的问题：每条样本是否都完成了任务，差距是否跨 seed 和模型成立。
